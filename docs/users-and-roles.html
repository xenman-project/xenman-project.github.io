Users and roles

XenMan controls access with three roles. Administrators manage users under Users.

Roles and permissions

RolePermissions
AdministratorAll tasks, including pools, hosts, storage, networking, updates, licensing, users and settings.
OperatorVM tasks on the assigned pools: create, import, start, stop, migrate, snapshot, console and snapshot schedules.
ViewerRead-only access to the assigned pools.

Operators and viewers see only the pools that an administrator assigns to them under Users.

Add a user

To add a user:

  1. Go to Users and select Add User.
  2. Enter the user name and select the role.
  3. For operators and viewers, select the pools.
  4. Set a password, or send an invitation by email if mail is configured.

Two-factor sign-in

Users can protect their account with a time-based code from an authenticator app, such as Microsoft Authenticator or Google Authenticator.

To turn on two-factor sign-in for your account:

  1. Go to Settings > Account.
  2. Turn on two-factor sign-in and scan the QR code with your authenticator app.
  3. Enter the code from the app to confirm.
  4. Store the ten recovery codes in a safe place. Each code works once.

Administrators can require two-factor sign-in for administrators or for all users under Settings > Security, and can reset it for a user under Users.

Sign in with Microsoft Entra ID

Users can sign in with their Microsoft account. XenMan takes the role from Entra ID app roles at every sign-in. MFA and Conditional Access are handled by Entra ID.

To set up Entra ID sign-in:

  1. In the Microsoft Entra admin center, create an app registration with platform Web and the redirect URI https://<xenman address>/api/auth/sso/callback.
  2. Create a client secret and copy its value.
  3. Create the app roles XenMan.Admin, XenMan.Operator and XenMan.Viewer.
  4. In Enterprise applications, assign users or groups to the roles. Set Assignment required to Yes.
  5. In XenMan, go to Settings > Security > Microsoft Entra ID. Enter the tenant ID, client ID, client secret and XenMan's address, then turn it on. Use Test to check the connection.

Note: Users without an app role cannot sign in. Pool access for operators and viewers is still set in XenMan under Users.

Optionally, allow password sign-in for administrators only. This keeps a way in when Entra ID cannot be reached.
