XenMan overview

XenMan is a web-based management console for XenServer and XCP-ng. You use it to manage pools, hosts and virtual machines (VMs) from a browser, without installing a Windows client. Many workflows follow XenCenter, including its checks and wording.

Capabilities

  • Pools and hosts – manage several pools at once, enter maintenance mode, designate a new pool coordinator, add and remove servers.
  • Virtual machines – create, import, start, stop, migrate, copy and delete VMs. Edit CPU, memory, disks, networks and boot settings, and open the console in the browser.
  • Storage and networking – create and repair storage repositories (SRs), including iSCSI. Manage networks, bonds, VLANs and the management interface.
  • Updates – update hosts one by one, with VMs moved away and back automatically.
  • Snapshot schedules – take VM snapshots hourly, daily or weekly.
  • GPU and PVS-Accelerator – manage physical GPUs, vGPUs and PVS read caching.
  • Monitoring – performance graphs, alerts, Recent Tasks and an audit log.
  • Users and security – Administrator, Operator and Viewer roles, two-factor sign-in, Microsoft Entra ID sign-in and HTTPS only.

Deployment options

XenMan is available in two forms:

  • Appliance – a ready-to-import XenServer VM (Debian 13). Recommended for most installations. It includes signed in-place updates and automatic Debian security updates.
  • Docker container – the image ghcr.io/xenman-project/xenman for an existing container host.

For details, see Install XenMan.

Scope

XenMan focuses on everyday pool and VM administration. The following tasks are not yet available: High Availability configuration, GFS2 clustered storage, OVF import, cross-pool storage migration, vApps, disaster recovery, Active Directory integration, Server Status Reports and Rolling Pool Upgrade. Keep XenCenter available for these tasks.

Note: XenMan is in beta. It is used daily in production, but test it on a non-critical pool before you rely on it.
