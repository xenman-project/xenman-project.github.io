System requirements

This article lists the requirements for running XenMan and for the systems it manages.

Managed systems

  • XenServer 8 or XCP-ng 8. XenMan is developed and tested on XenServer 8.4.
  • XenServer 9. XenMan works with XenServer 9, but it is not yet fully tested.
  • A user account on the pool with full administrative rights, typically root.

Browsers

Use a current version of Microsoft Edge, Google Chrome, Mozilla Firefox or Safari. The browser must allow cookies and WebSocket connections to XenMan.

Appliance sizing

ResourceDefault
vCPUs2
Memory2 GB
Disk20 GB (about 1.5 GB used after import)
Operating systemDebian 13, minimal

Note: For the Docker container, plan the same memory. XenMan requires Node.js 24 when you run it without a container.

Network ports

DirectionPortPurpose
Browser → XenMan443 (appliance) or 3001 (Docker)Web interface over HTTPS
Browser → XenMan80 (appliance) or 3000 (Docker)Redirect to HTTPS only
XenMan → every host443XenAPI, consoles, performance data, imports
XenMan → pool coordinator22Optional: VM export over SSH
XenMan → mail server25, 465 or 587Optional: notifications and password resets
XenMan → login.microsoftonline.com443Optional: Microsoft Entra ID sign-in

Important: XenMan must reach every host of a pool directly, not only the coordinator. XenServer serves consoles and performance data from each host. For pools behind NAT, see Pools at other sites.
