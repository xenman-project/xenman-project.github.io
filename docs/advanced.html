Advanced configuration

This article describes configurations for pools at other sites and for XenMan behind a reverse proxy.

Pools at other sites

XenMan can manage a pool that it reaches only through NAT, for example a firewall's virtual IP in front of a pool at another site. Without further configuration, consoles, performance graphs, imports and SSH exports do not work, because XenServer provides them at each host's own management address. XenCenter has the same limitation.

To make these features work:

  1. When you add the pool, or later under Settings > Pools > Edit, turn on Hosts are behind NAT.
  2. For each host, enter the address at which XenMan reaches it. Use either an address per host with port 443 forwarded, or one address with a port per host, such as 203.0.113.10:4431.
  3. Save the settings.

Important: Every host must be reachable, and the firewall must pass TLS through unchanged. XenMan checks every host's certificate as usual.

Consoles behind a reverse proxy

When XenMan runs behind a reverse proxy such as NetScaler, configure the proxy as follows:

  • Enable WebSocket in the HTTP profile of the virtual server.
  • Do not apply compression, App Firewall or bot checks to /api/vnc-proxy.
  • Use a TCP profile with a large window and SACK, and turn off Nagle.
  • Set client and server idle timeouts of at least a few minutes.

Start XenMan with XENMAN_TRUST_PROXY=1 so that it takes the client address and X-Forwarded-Proto: https from the proxy. The proxy must set both headers.

To compare console performance, open View > Connection info in the console. It shows frames per second, data rate and encoding.
